🏗️ Project Pipeline: LLM Query Routing Optimizer

The Story
A mid-size AI company runs a customer support + internal knowledge base chatbot. They're spending too much on LLM API calls. Different query types don't all need GPT-4 — a simple FAQ doesn't need the same model as a complex legal document summary. Goal: route each query type to the cheapest model that still meets quality requirements.

Step 2 — Formulate the LP Problem
Decision variable: x[i][j] = 1 if query type i is assigned to model j, else 0
Objective: Minimize total monthly cost
Minimize: Σ x[i][j] × volume[i] × avg_tokens[i] × cost_per_token[j]
Constraints:

Each query type assigned to exactly 1 model
Assigned model's quality ≥ query's min quality requirement
Optional: budget cap constraint (e.g. max $500/month)

This is a Binary Integer LP — perfect for PuLP.

Step 3 — Solve with PuLP
Write the model, solve it, extract which model handles which query type and what the total monthly cost is.

Step 4 — Baseline Comparison (the "business impact" part)
Calculate what it would cost if you routed everything to GPT-4o (worst case / naive approach). Then compare:
Naive cost (all GPT-4):   $X
Optimized cost:           $Y
Savings:                  $Z (P%)
This is your headline result — makes the project feel real.

Step 5 — Data Analysis & Visualization
4 plots:

Libraries: matplotlib, pandas, pulp — all free.

Step 6 — Sensitivity Analysis (makes it 10x more impressive)
Ask: what happens if GPT-4o drops its price by 50%? Does the routing change?
Re-run the LP with modified costs and show how assignments shift. This is what real ops research teams do.
